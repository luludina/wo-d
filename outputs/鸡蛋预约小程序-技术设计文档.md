# 鸡蛋预约小程序技术设计文档

版本：V1.0（评审稿）  
状态：待技术评审  
更新时间：2026-09-24

## 1. 设计目标

在单一业务空间内，为微信小程序提供成员管理、鸡蛋预约、供餐日管理、站内通知和管理员审计能力。首版优先保证规则正确、部署简单和维护成本低，不引入微服务、Redis、消息队列或完整监控平台。

## 2. 技术选型

### 2.1 小程序端

- 微信原生小程序；
- TypeScript；
- WXML + WXSS；
- 微信开发者工具；
- 原生组件 + 项目自建组件，暂不引入完整 UI 组件库；
- 微信专属能力集中封装，页面不散落调用 `wx.*`；
- 纯业务规则和 API 类型与页面逻辑分离。

### 2.2 后端

- Node.js LTS；
- TypeScript；
- Fastify；
- TypeBox：请求、响应校验和 OpenAPI Schema；
- MongoDB 官方 Node.js Driver；
- REST + JSON；
- 模块化单体架构。

### 2.3 基础设施

- Docker Compose；
- Nginx；
- MongoDB 单节点副本集；
- 已备案 HTTPS 域名；
- 服务器持久化卷保存头像和数据库数据。

## 3. 总体架构

```text
微信原生小程序
    │ HTTPS / REST
    ▼
Nginx
    ├── /api/*       → Fastify API
    └── /uploads/*   → 头像持久化卷
                         │
                         ▼
                 MongoDB 单节点副本集
```

系统采用单一后端服务和单一数据库，不设计组织、群组、租户或微服务边界。

## 5. 后端模块

### 5.1 Auth

- 接收 `wx.login()` 临时 code；
- 调用微信 `jscode2session`；
- 使用 `openid` 查找或创建用户；
- 创建、续签和撤销服务端 Session；
- 不提供账号密码登录。

### 5.2 Members

- 成员资料；
- 首次申请、审核通过、拒绝；
- 停用与重新启用；
- 管理员任命与撤销；
- 最后一名管理员保护。

### 5.3 Reservations

- 单日实时保存；
- 按周、按月和复制批量填报；
- 每日数量 0～5；
- 当前月与下一个月窗口校验；
- 09:00 动态锁定；
- 每位成员每天只保留最新预约状态。

### 5.4 Meal Days

- 周一至周五默认开放；
- 周六、周日默认关闭；
- 只保存管理员对具体日期的覆盖；
- 单日和日期范围批量设置；
- 预览、确认和并发重新校验。

### 5.5 Notifications

- 按接收用户生成通知；
- 最新未读通知；
- 通知中心分页；
- 已读状态；
- 通知保留 12 个月。

### 5.6 Audit

- 成员审核；
- 供餐日设置；
- 成员停用与启用；
- 管理员任命与撤销；
- 首位管理员初始化。

## 6. 身份与会话

### 6.1 登录流程

```text
小程序启动
  → 读取本地 Session Token
  → Token 有效：获取当前用户
  → Token 无效：静默调用 wx.login()
  → 后端用 code 换取 openid
  → 创建新 Session Token
  → 写入小程序本地缓存
```

`wx.login()` 本身不弹出用户授权框。手机号获取、头像选择等需要用户动作的能力与登录会话分开处理。

### 6.2 Session 安全

- 小程序使用 `Authorization: Bearer <token>`；
- 数据库只保存 Token 哈希；
- Session 设有效期并通过 TTL 索引自动清理；
- Token 失效后通过 `wx.login()` 静默重建；
- 停用成员时撤销其全部 Session；
- 权限判断每次以数据库当前成员状态为准。

## 7. MongoDB 数据模型

### 7.1 users

```ts
interface User {
  _id: ObjectId
  openid: string
  avatarUrl?: string
  nickname?: string
  realName?: string
  department?: string
  phone?: string
  memberStatus: 'draft' | 'pending' | 'approved' | 'rejected' | 'disabled'
  isAdmin: boolean
  rejectionReason?: string
  createdAt: Date
  updatedAt: Date
}
```

索引：

- `unique(openid)`；
- `(memberStatus, createdAt)`；
- `(isAdmin, memberStatus)`。

### 7.2 sessions

```ts
interface Session {
  _id: ObjectId
  userId: ObjectId
  tokenHash: string
  expiresAt: Date
  createdAt: Date
  lastUsedAt: Date
}
```

索引：

- `unique(tokenHash)`；
- TTL `expiresAt`；
- `(userId, expiresAt)`。

### 7.3 meal_day_overrides

```ts
interface MealDayOverride {
  _id: ObjectId
  date: string // YYYY-MM-DD
  status: 'open' | 'closed'
  reason?: string
  version: number
  updatedBy: ObjectId
  createdAt: Date
  updatedAt: Date
}
```

索引：`unique(date)`。

无覆盖记录时，后端按星期实时计算默认状态。

### 7.4 reservations

```ts
interface Reservation {
  _id: ObjectId
  memberId: ObjectId
  date: string // YYYY-MM-DD
  quantity: number // 0..5
  status: 'active' | 'cancelled'
  cancelledReason?: 'meal_day_closed' | 'member_disabled'
  createdAt: Date
  updatedAt: Date
}
```

索引：

- `unique(memberId, date)`；
- `(date, status)`；
- `(memberId, date)`。

系统不保存预约事件历史。重新预约时直接覆盖当前记录为最新状态。

### 7.5 notifications

```ts
interface Notification {
  _id: ObjectId
  receiverId: ObjectId
  type: string
  title: string
  content: string
  relatedDate?: string
  isRead: boolean
  readAt?: Date
  createdAt: Date
  expiresAt: Date
}
```

索引：

- `(receiverId, isRead, createdAt)`；
- `(receiverId, createdAt)`；
- TTL `expiresAt`。

### 7.6 audit_logs

```ts
interface AuditLog {
  _id: ObjectId
  operatorId: ObjectId
  action: string
  targetType: string
  targetId?: string
  before?: Record<string, unknown>
  after?: Record<string, unknown>
  reason?: string
  requestId: string
  createdAt: Date
}
```

索引：

- `(operatorId, createdAt)`；
- `(targetType, targetId, createdAt)`；
- `(action, createdAt)`。

## 8. 日期与时间规则

- 供餐业务日期使用 `YYYY-MM-DD` 字符串；
- `createdAt`、`updatedAt` 等事件时间使用 MongoDB UTC `Date`；
- 业务时区固定为 `Asia/Shanghai`；
- 当前月与下个月按上海时区计算；
- 当日 09:00 锁定状态实时计算，不写入数据库；
- API 返回预约时附带计算字段 `isLocked`；
- 所有写接口必须在服务端重新校验截止时间。

## 9. 核心一致性设计

### 9.1 单日预约

- 服务端校验成员状态、预约窗口、有效供餐状态和截止时间；
- 使用 `(memberId, date)` 唯一索引执行 upsert；
- 同一成员多设备并发修改采用最后一次成功写入；
- 客户端只以服务端返回结果为保存成功依据。

### 9.2 批量预约

- 客户端先展示变更日期和数量；
- 服务端重新校验每个日期；
- 跳过关闭供餐日；
- 批量结果要求整体成功或整体失败；
- 使用 MongoDB 事务完成多个日期的 upsert。

### 9.3 批量供餐日设置

分为两步：

```text
POST /api/v1/admin/meal-days/batch/preview
POST /api/v1/admin/meal-days/batch/apply
```

预览返回目标日期、状态变化、受影响成员数和预计取消预约数。确认执行时，后端重新查询覆盖版本和受影响预约；若状态已变化，则拒绝执行并要求重新预览。

一个事务内完成：

1. 写入供餐日覆盖；
2. 将受影响预约改为 `cancelled`；
3. 为每位审核通过成员生成通知；
4. 写入管理员操作日志。

事务发生瞬时错误时执行有限次数重试。请求使用幂等键，避免重复通知。

### 9.4 成员停用

一个事务内完成：

1. 用户状态改为 `disabled`；
2. 取消其所有尚未锁定的未来有效预约；
3. 创建成员状态通知；
4. 写入操作日志；
5. 撤销该成员全部 Session。

已经过当日 09:00 的预约不修改。

## 11. 头像处理

- 使用微信 `chooseAvatar` 获得临时文件；
- 小程序上传到后端；
- 后端校验 MIME、扩展名和文件大小；
- 使用随机文件名，不采用用户原文件名；
- 保存到独立 Docker 持久化卷；
- Nginx 只读提供 `/uploads/avatars/*`；
- 头像目录纳入备份；
- 更换头像后异步清理旧文件；
- 后续多实例部署时迁移到对象存储。

## 12. 部署方案

### 12.1 容器

```text
nginx
api
mongodb
backup
```

MongoDB 配置为单节点副本集，数据库端口不暴露公网。Nginx 负责 HTTPS 终止、API 反向代理和头像静态访问。

### 12.2 配置

生产配置通过服务器 `.env` 注入，不提交代码仓库：

```text
WECHAT_APP_ID
WECHAT_APP_SECRET
MONGO_URI
SESSION_SECRET
API_DOMAIN
TZ=Asia/Shanghai
```

日志禁止输出 AppSecret、Session Token、手机号等敏感信息。

### 12.3 发布

首版不拆开发、测试和生产服务器环境：

- 日常开发使用本地服务和本地 MongoDB 副本集；
- 生产数据库不用于开发调试；
- 功能确认后手动构建并部署 Docker 镜像；
- 索引和初始化脚本必须可重复执行；
- 发布前执行本地接口冒烟测试；
- 后续再增加 CI/CD。

## 13. 首位管理员初始化

1. 首位管理员正常登录并提交资料；
2. 系统创建待审核用户；
3. 在服务器容器内运行：

```bash
pnpm admin:promote --user-id <用户ID>
```

4. 脚本将用户设为已通过成员和管理员；
5. 写入初始化审计日志；
6. 后续管理员任命全部从小程序完成。

不提供公网管理员初始化接口。

## 14. 日志与健康检查

- Fastify 输出 JSON 结构化日志；
- 每个请求生成 `requestId`；
- 提供 `/health/live` 和 `/health/ready`；
- Docker 配置健康检查和自动重启；
- Nginx 记录访问日志；
- 日志按日期或大小轮转；
- 异常日志包含路径、业务错误码和 `requestId`；
- 首版不引入 ELK、Prometheus 或消息队列。

## 15. 备份与恢复

- MongoDB 使用 Docker 持久化卷；
- 每日执行 `mongodump`；
- 备份压缩并加密；
- 保留 7～30 天；
- 至少同步一份到独立存储；
- 头像持久化卷同时备份；
- 定期执行恢复演练；
- MongoDB 不暴露公网端口。

## 16. 工程质量底线

完整验收由专业测试人员负责，工程侧仍保留关键自动化检查：

- 每人每天数量只能为 0～5；
- 当前月与下个月之外不可预约；
- 09:00 后不可修改；
- 关闭供餐日不计入有效总数；
- 同一成员同一天只有一条预约；
- 供餐关闭事务必须整体成功或整体失败；
- 停用成员不能访问业务接口；
- 最后一名管理员不能被撤销。

## 17. 首版明确不引入

- 微服务；
- Redis；
- 消息队列；
- 事件溯源和预约历史集合；
- 完整 UI 组件库；
- 对象存储；
- 多租户或多群组；
- 独立 Web 管理后台；
- 测试服务器环境；
- 微信订阅消息；
- 完整可观测性平台。
